# 下一阶段执行方案：核心循环与 UI 稳定性

## 1. 目标

下一阶段暂不继续扩充大量章节、词缀或地图数据，先解决 UI 状态不稳定问题，并打通一条可重复体验的核心循环：

```text
进入区域
  -> 探索
  -> 战斗
  -> 获得装备或技能宝石
  -> 背包查看
  -> 装备或镶嵌
  -> 属性/技能伤害变化
  -> 完成任务并领取奖励
  -> 进入下一个区域
```

阶段完成后，玩家应能在 15 到 30 分钟内完成一段完整、有反馈、有成长的游戏流程。

## 2. 当前问题

### P0：必须先处理

1. `startGame()` 可能重复调用 `initGameUI()`，导致事件重复绑定。
2. 区域选择、探索、战斗、地图仪由多个 DOM 显示状态分别控制，没有统一主区域状态。
3. 战斗中可以点击地图导航，可能导致战斗面板和地图仪同时显示。
4. 关闭地图仪固定返回区域选择，无法恢复进入地图仪前的探索场景。
5. 装备和技能 UI 使用全局 `[data-slot]`、`[data-key]` 选择器，未来增加 HUD 后可能更新错误节点。

### P1：核心循环阻塞

1. 战斗掉落技能宝石仍显示“未实现”。
2. 背包宝石标签仍显示“宝石系统（未实现）”。
3. 任务有列表，但击杀、区域完成、奖励领取的反馈不完整。
4. 新角色没有合理的起始装备，装备和属性成长无法在早期被感知。
5. 宝石镶嵌和取下流程没有形成稳定闭环。

### P2：后续优化

1. `panel` 参数仍使用 `string`，缺少合法值约束。
2. 旧的 Q/W/S 操作分支仍保留，但底部按钮已经移除。
3. 地图列表 CSS 存在重复定义。
4. 当前没有自动化测试覆盖 UI 导航和主区域切换。

## 3. 实施顺序

必须按以下顺序执行，完成前一阶段后再进入下一阶段。

---

## Phase 1：建立 UI 状态基础设施

### 目标

保证任何入口都只能显示一个主区域模式，且事件只绑定一次。

### 任务

- [ ] 在 `UIController` 中增加事件绑定状态，例如 `private eventsBound = false`。
- [ ] 让 `bindEvents()` 具备幂等性，重复调用时直接返回。
- [ ] 确认 `PassiveTreeUI.init()` 不会重复给同一容器注册事件。
- [ ] 定义主区域状态类型：

```typescript
type MainView = "menu" | "zone-select" | "scene" | "combat" | "map-device";
```

- [ ] 增加统一方法：

```typescript
private setMainView(view: MainView): void;
private getMainView(): MainView;
```

- [ ] 由 `setMainView()` 统一控制：
  - `#zone-select-display`
  - `#scene-display`
  - `#combat-display`
  - `#map-device-display`
- [ ] `startCombat()`、`endCombat()`、`openMapDevice()`、`closeMapDevice()`、`enterZone()`、`openSelectedMap()` 全部改为调用 `setMainView()`。
- [ ] 战斗状态下禁止打开地图仪和切换会改变主区域的入口。
- [ ] 地图仪打开前记录上一个主区域视图，关闭时恢复原视图。

### 验收标准

- 新游戏后重复点击导航，不会出现重复日志或重复事件。
- 加载存档后点击技能一次只执行一次攻击。
- 战斗中点击地图图标只显示提示，不改变主区域。
- 从探索场景打开并关闭地图仪后，仍回到原探索场景。
- 任意时刻 `#zone-select-display`、`#scene-display`、`#combat-display`、`#map-device-display` 最多只有一个可见。

---

## Phase 2：收紧面板导航和 DOM 选择器

### 目标

让左侧导航成为唯一的信息面板入口，并避免全局选择器互相影响。

### 任务

- [ ] 定义面板类型：

```typescript
type UtilityPanel =
  | "character"
  | "equipment"
  | "skills"
  | "inventory"
  | "quests"
  | "log"
  | "save";
```

- [ ] 将 `showUtilityPanel(panel: string)` 和 `handleNavPanel(panel: string)` 改为使用明确类型或运行时校验。
- [ ] 为面板增加容器引用或限定选择器：
  - 装备只查询 `[data-panel-content="equipment"]`
  - 技能只查询 `[data-panel-content="skills"]`
  - 背包只查询 `[data-panel-content="inventory"]`
- [ ] 普通面板统一使用 `showUtilityPanel()` 打开和关闭。
- [ ] 天赋树、地图仪保留特殊入口，但明确它们不是普通抽屉面板。
- [ ] `closePassiveTree()` 清理天赋导航 active 状态。
- [ ] 统一主菜单和游戏内存档容器，避免同时存在两套 `menu-saves` 查询分支。
- [ ] 合并 `mapstyles.css` 中重复的 `.map-list` 定义。

### 验收标准

- 左侧每个普通图标点击后只激活一个抽屉 section。
- 当前面板再次点击可以关闭，再次点击可以重新打开。
- 装备和技能面板各自更新，不影响其他面板。
- 天赋树关闭后左侧 active 状态正确。
- 地图仪不会把地图列表写入背包容器。

---

## Phase 3：补齐战斗掉落和装备成长

### 目标

让玩家在第一次战斗后就能获得并使用成长内容。

### 任务

- [ ] 实现技能宝石掉落数据，不再写入“未实现”日志。
- [ ] 在 `Player` / `Inventory` 中增加或确认宝石存储结构。
- [ ] 背包“宝石”标签显示实际宝石列表。
- [ ] 宝石列表支持查看名称、颜色、等级、需求等级和描述。
- [ ] 新游戏提供至少一件起始武器和一件基础防具。
- [ ] 提高前期装备掉落的可见性，确保玩家在前几次探索中能获得装备。
- [ ] 背包装备点击打开装备详情，而不是直接执行隐式操作。
- [ ] 装备详情明确显示“装备”按钮、需求和属性。
- [ ] 装备后刷新：
  - 顶部生命/魔力/护盾
  - 角色属性面板
  - 防御与抗性
  - 技能伤害预览
- [ ] 统一装备、天赋、基础属性的累加逻辑，避免覆盖已有加成。

### 验收标准

- 新游戏有可用起始装备和技能。
- 至少一次战斗能获得装备或技能宝石。
- 点击背包物品可以查看详情并装备。
- 装备前后属性和技能伤害有可见变化。
- 普通、魔法、稀有物品的颜色和详情显示正确。

---

## Phase 4：打通宝石镶嵌和技能组

### 目标

让“获得宝石”能够真正改变技能构筑。

### 任务

- [ ] 在装备详情中显示孔颜色、孔数量和链接关系。
- [ ] 点击空孔打开可用宝石选择。
- [ ] 校验宝石颜色和装备需求。
- [ ] 支持将主动宝石镶嵌到孔中。
- [ ] 支持将辅助宝石镶嵌到相连孔中。
- [ ] 支持从孔中取下宝石并返回背包。
- [ ] 镶嵌或取下后刷新技能组计算。
- [ ] 在技能面板显示：
  - 主动技能
  - 辅助技能
  - 总伤害
  - 伤害类型
  - 魔力消耗
- [ ] 战斗技能按钮使用最新的技能组数据。

### 验收标准

- 一件有孔装备可以镶嵌宝石。
- 辅助宝石只有在链接且标签匹配时才生效。
- 取下宝石后背包数量正确恢复。
- 镶嵌前后技能伤害显示不同。
- 战斗中实际伤害与技能面板计算结果一致。

---

## Phase 5：接入一条完整任务线

### 目标

让任务面板成为推进核心循环的实际系统，而不是静态列表。

### 任务

- [ ] 选择一条最小主线任务，例如“镇外的异动”。
- [ ] 定义任务状态：`available / active / completed / claimed`。
- [ ] 明确任务完成条件：击杀指定怪物数量或完成指定区域。
- [ ] 探索和战斗结束时更新任务进度。
- [ ] 任务面板显示：
  - 当前进度
  - 目标数量
  - 完成状态
  - 奖励内容
- [ ] 完成任务时显示明显反馈。
- [ ] 点击领取后发放经验、通货或技能宝石。
- [ ] 奖励领取后不再重复显示。
- [ ] 存档和加载后保留任务状态。

### 验收标准

```text
接受任务
  -> 进入指定区域
  -> 击杀目标
  -> 面板显示完成
  -> 点击领取
  -> 奖励进入玩家状态
  -> 任务变为已领取
```

必须验证刷新页面或加载存档不会重复领取奖励。

## Phase 6：补测试和回归验证

### 最低测试范围

如果项目继续使用轻量前端结构，可以先增加纯 TypeScript 单元测试或可调用的测试方法，至少覆盖：

- `setMainView()` 只显示一个主区域。
- `bindEvents()` 重复调用不会增加监听器。
- 战斗中不能打开地图仪。
- 地图仪关闭后恢复之前的主区域。
- 导航重复点击可以打开/关闭抽屉。
- 装备更新不会修改技能或背包面板。
- 宝石镶嵌和取下保持库存数量一致。
- 任务奖励只能领取一次。
- 存档和加载后保留地图仪、装备、宝石和任务状态。

### 手动回归流程

1. 新游戏。
2. 点击角色、装备、技能、背包、任务、日志。
3. 重复点击当前图标，确认抽屉关闭。
4. 进入区域并探索。
5. 触发战斗，连续点击技能。
6. 检查敌方行动只执行一次。
7. 尝试在战斗中打开地图仪。
8. 战斗结束后检查装备、宝石和经验掉落。
9. 装备物品并检查角色属性。
10. 打开装备详情并镶嵌/取下宝石。
11. 完成任务并领取奖励。
12. 保存、刷新、加载，再重复检查状态。
13. 使用 700px 以下窗口检查导航和抽屉遮挡。

## 4. 不在本阶段处理的内容

以下内容先不要加入本阶段，避免范围失控：

- 完整 10 章剧情
- 大规模新增装备基底和词缀
- 300+ 主动技能
- 完整交易市场
- 完整 Atlas 天赋树
- Maven、征服者等终局 Boss
- 高级精髓、化石和复杂腐化系统
- 大规模视觉重做

## 5. 建议提交顺序

每个阶段独立完成并验证后再进入下一阶段：

1. `fix(ui): prevent duplicate bindings and centralize main view`
2. `refactor(ui): scope navigation panel selectors`
3. `feat(loot): enable equipment and gem drops`
4. `feat(socket): complete gem socketing flow`
5. `feat(quest): complete first playable quest loop`
6. `test(ui): add navigation and progression regression checks`

## 6. 完成定义

本方案完成的标准不是“新增了多少数据”，而是玩家可以稳定完成以下流程：

```text
新游戏
  -> 进入区域
  -> 探索并战斗
  -> 获得装备/宝石
  -> 在左侧导航打开背包
  -> 查看并装备物品
  -> 打开属性面板看到数值变化
  -> 镶嵌宝石改变技能
  -> 完成任务领取奖励
  -> 保存并加载后状态不丢失
```

只有这条流程稳定后，才继续扩展 POE1 的内容深度和终局系统。
