# 待完善内容：当前版本 vs PoE1

> 试玩范围：新游戏 → 进入枯萎森林 → 探索入口 → 地图仪 → 地图选择/开启。当前版本可以正常构建，核心 UI 与部分系统已经具备。
>
> 结论：现在更像“PoE 主题的回合制文字 Demo”，距离 PoE1 的完整刷图 ARPG 体验，最大差距不在面板数量，而在**战斗决策、掉落循环、Build 反馈、内容密度和终局重复游玩**。

## 一、试玩中最明显的问题（P0）

### 1. 新手状态与内容入口不一致
- 点击“新游戏”后角色直接是 **Lv.12**，但区域列表从 Lv.1 开始，且第一张地图区域内容明显偏低级。
- “继续游戏”在没有存档时仍可点击，缺少明确的禁用/空状态提示。
- 建议：新游戏固定从 Lv.1、城镇/第一章开始；测试角色入口单独放到开发菜单。

### 2. 探索和战斗的核心反馈不足
- 探索按钮只产生文字事件，随后延迟进入战斗；缺少“遭遇类型、怪物数量、危险预警、逃跑/跳过”等选择。
- 战斗界面显示敌人血条，但没有清晰呈现当前行动者、行动顺序、技能冷却/魔力不足、命中/暴击/异常状态等关键决策信息。
- PoE1 的爽点来自即时攻击、走位、技能范围与敌群反应；当前实现更接近“点击技能→等待敌人回合”。
- 建议：先做稳定的战斗状态机，再增加战斗事件日志、行动条、敌人意图和技能结果摘要。

### 3. 地图仪是 UI 入口，尚未形成真正的地图循环
- 地图虽然有 T1-T16、前后缀和数量/品质字段，但试玩中地图选择后不容易确认“已选中什么”，地图词缀与怪物强度/掉落的实际影响也不明显。
- `mapDevice.completeMap()` 只生成少量固定奖励，地图词缀没有完整贯穿怪物数量、怪物生命、危险类型、掉落数量/品质。
- 建议：地图详情卡固定展示“区域等级、词缀、预估危险、预计奖励”；开启后生成一张有进度的地图实例，完成条件与掉落受词缀真实影响。

## 二、与 PoE1 的系统差距（P1）

### 4. 装备系统缺少“可比较、可决策”的价值
已有：基础物品、稀有度、词缀、插槽、品质、通货操作。

缺少：
- 装备对比（当前装备 vs 新掉落）。
- 物品过滤/按等级与槽位排序。
- 词缀池合法性、物品等级限制、前后缀数量和重量的严格规则。
- 六洞/六连等关键目标，以及链接失败/成功的长期追求。
- 传奇装备的固定机制与独特 Build 方向。

### 5. 技能宝石系统没有形成完整 Build
已有主动/辅助宝石和插槽链接雏形。

缺少：
- 宝石经验、升级、降级/锁定升级。
- 辅助宝石生效条件、标签匹配、伤害与特殊效果的可靠展示。
- 一键替换、技能栏配置、主动技能/辅助技能的清晰区分。
- 光环保留、触发技能、诅咒、图腾、召唤、持续伤害等 PoE1 常见组合。
- 当前技能栏只有 3 个槽，且底部按钮文案与实际技能组可能脱节。

### 6. 天赋树规模和规则远低于 PoE1
- 当前更像可点击节点图，缺少职业起点、路径规划、关键节点取舍、升华职业和珠宝槽。
- 取消天赋时需要校验“末端节点”，不能简单 `pop()` 任意节点。
- 缺少天赋搜索、路径高亮、重置成本和 Build 导入/导出。

### 7. 防御与伤害模型仍是简化版
- 只有生命、魔力、护甲、闪避、能量护盾、四抗的展示。
- 缺少护甲/闪避的等级化收益、格挡、法术压制、元素异常免疫、混沌抗性策略、生命回复/吸血/再生等。
- 异常状态虽有类型定义，但尚未形成完整的施加、持续、抵抗、移除与 UI 呈现。
- 需要加入伤害计算测试，避免“面板数值看似变化，但战斗结果不变”。

## 三、内容和长期留存差距（P1/P2）

### 8. 章节内容密度不足
- 数据定义了多章任务，但可玩区域目前只落地到第 2 章的一小部分，且任务与区域完成条件没有完全一一对应。
- NPC 商店、事件类型（商店、NPC、陷阱、宝藏）有定义，但试玩中缺少可交互的完整事件界面。
- 建议：每章至少补齐“城镇 → 3~5 个区域 → 支线任务 → Boss → 新机制”的闭环。

### 9. 缺少 PoE1 式终局成长
优先补：
- 地图图鉴/完成奖励。
- 地图等级推进与掉落正反馈。
- 地图改造、瓦尔化/特殊地图结果。
- 终局 Boss、守护者、赛季机制。
- 角色死亡代价、经验惩罚、地图失败处理。
- 目前 `abandonMap()` 会直接放弃当前地图，需明确是否保留已获得奖励、地图是否消耗和是否算失败。

### 10. 经济系统还不像 PoE
- 通货种类已有基础，但缺少价格/用途引导、批量使用、交易价值和配方系统。
- 镜像、神圣石等高阶通货在当前阶段过早出现，容易让低等级经济失去目标感。
- 建议按章节解锁通货，并增加“推荐用途/可影响词缀”的详情说明；后续再做配方与 NPC 兑换。

## 四、产品体验与技术债（P2）

### 11. UI 可用性
- 地图列表重复文本较多，选择态不明显。
- 重要操作依赖日志，缺少 toast、奖励弹窗、升级动画和声音/视觉反馈。
- 移动端/窄屏布局需要专项检查；目前信息面板和底部操作栏容易挤压。
- 应统一按钮快捷键与实际功能，避免“底部显示技能名但内部技能组未配置”的困惑。

### 12. 状态一致性与测试
- 探索奖励、战斗奖励、首胜宝石奖励存在多处发放逻辑，后续容易重复发奖。
- 存档需要版本号、迁移策略和异常数据兜底。
- 建议补齐纯函数测试：伤害计算、护甲减伤、词缀生成、地图词缀效果、任务状态机、存档序列化。
- 加一条最小 E2E 流程：新游戏 → 进入区域 → 探索 → 战斗 → 获得掉落 → 装备 → 开地图 → 完成地图 → 存档/读档。

## 五、建议开发顺序

### Milestone 1：把 Demo 变成可玩的核心循环（最高优先级）
1. 修正新游戏起始状态为 Lv.1，并提供独立测试入口。
2. 重做一次战斗状态机：行动者、技能资源、敌人回合、胜负、奖励只能结算一次。
3. 完善掉落与装备对比，保证“打怪 → 掉落 → 装备 → 变强”可感知。
4. 地图选择态、地图词缀生效和地图完成奖励闭环。

### Milestone 2：形成 PoE 风格 Build
1. 完善主动/辅助宝石标签与支持逻辑。
2. 宝石升级与技能栏配置。
3. 天赋路径校验、职业起点、升华/珠宝槽。
4. 防御、异常、回复和抗性机制补全。

### Milestone 3：内容与终局
1. 补齐章节区域和任务交互。
2. 加入 NPC 商店、配方和章节通货节奏。
3. 地图图鉴、终局 Boss、赛季词缀。
4. 角色死亡、经验风险和长期目标。

## 一句话验收标准

玩家应该能在 10 分钟内完成：**进入区域 → 做出一次战斗选择 → 获得一个有意义的掉落 → 装备或改造它 → 感觉角色明显变强 → 用新能力挑战更高等级地图**。当前版本已经有这些名词和入口，但这条因果链的反馈还不够强，是最值得优先完善的方向。
