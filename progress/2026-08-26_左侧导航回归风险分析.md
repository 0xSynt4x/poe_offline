## 潜在回归点

### P1：重复初始化会重复绑定事件

位置：`src/ui/controller.ts:300-340, 357-448`

`startGame()` 每次调用 `initGameUI()`，而 `initGameUI()` 每次调用 `bindEvents()`。加载存档时会再次执行这条链，但页面上的导航、键盘、技能、药剂、动作按钮和场景按钮节点仍然存在，因此可能重复绑定：

- 点击导航触发多次 `handleNavPanel`
- 键盘药剂事件执行多次
- 技能点击可能重复消耗回合或重复写日志
- 天赋树 `PassiveTreeUI.init()` 也会重新绑定容器事件

复现路径：新游戏 -> 保存 -> 返回/加载同一存档 -> 重复点击技能或导航。

建议：将 `bindEvents()` 改为一次性初始化，或增加 `eventsBound` 标志；`PassiveTreeUI` 也应避免在同一容器重复注册事件。

### P1：地图仪入口可在战斗中打开，可能与战斗面板同时显示

位置：`src/ui/controller.ts:467-484, 1819-1848`

`handleNavPanel("map")` 无战斗状态检查，直接调用 `openMapDevice()`。`openMapDevice()` 只隐藏区域选择和探索面板，没有处理 `#combat-display`。战斗中点击地图图标时，地图仪可能和战斗显示同时存在，玩家还能改变当前主区域模式。

复现路径：进入区域 -> 探索触发战斗 -> 点击左侧地图图标。

建议：战斗中禁止打开地图仪并写入日志，或建立统一的主区域模式状态机，保证地图/战斗/探索只能有一个激活。

### P1：关闭地图仪不会恢复进入前的主区域

位置：`src/ui/controller.ts:1801-1816`

`closeMapDevice()` 固定执行：

- 隐藏地图仪
- 显示区域选择
- 打开角色属性抽屉

如果玩家从探索场景打开地图仪，关闭后会被强制送回区域选择，当前区域场景和探索进度的视觉状态丢失。

复现路径：进入枯萎森林 -> 点击地图图标 -> 点击关闭。

建议：打开地图仪前保存 `previousMainView`，关闭时恢复 `zone-select`、`scene` 或 `combat`；战斗状态应直接禁止地图仪。

### P1：天赋模态框关闭后导航激活态可能残留

位置：`src/ui/controller.ts:467-484, 721-727`

点击天赋图标会关闭抽屉并将天赋图标设为 active，但 `closePassiveTree()` 只隐藏 `#passive-modal`，不会清除 active 状态或恢复角色面板。

结果：天赋树已经关闭时，左侧仍可能显示天赋图标为当前激活入口，用户无法从视觉上判断当前是否有面板打开。

建议：在 `closePassiveTree()` 中调用 `setNavActive("character")` 或清除 active 状态，并按产品设计决定是否重新打开角色抽屉。

### P1：全局选择器会限制未来 HUD 扩展

位置：`src/ui/controller.ts:1285-1350`

以下更新逻辑使用全局选择器：

```typescript
document.querySelector(`[data-slot="${slot}"] .slot-content`)
document.querySelector(`[data-key="${i + 1}"] .skill-content`)
```

当前页面每类节点只有一份，所以可以工作。但如果未来在战斗 HUD、装备比较窗口或快捷技能栏复用同样的 `data-slot` / `data-key`，更新和点击会命中第一份节点，造成面板与实际战斗 HUD 不一致。

建议：限定到 `data-panel-content="equipment"`、`data-panel-content="skills"` 容器内，或为装备/技能区使用独立 ID。

### P2：`panel` 使用 `string`，非法导航值不会被拦截

位置：`src/ui/controller.ts:467-522`

`handleNavPanel(panel: string)` 和 `showUtilityPanel(panel: string)` 没有使用联合类型。若 HTML 中的 `data-panel` 拼写错误，代码仍会打开抽屉，但没有任何 `[data-panel-content]` 被激活，形成空抽屉。

建议：定义：

```typescript
type UtilityPanel = "character" | "equipment" | "skills" | "inventory" | "quests" | "log" | "save";
```

对特殊入口单独定义类型或在入口处校验。

### P2：旧快捷键分支已无对应按钮

位置：`src/ui/controller.ts:686-704`、`src/index.html:260-278`

底部 `Q: 查看`、`W: 天赋`、`S: 存档` 已移除，只保留 1、2、3 和提示文本；但 `handleAction()` 仍保留 Q/W/S 分支。当前不是功能错误，但属于旧入口残留，后续维护者可能误以为这些快捷键仍被绑定。

建议：要么增加明确的键盘绑定，要么删除死分支并更新控制台命令说明。

### P2：地图列表存在兼容性回退，可能误写背包

位置：`src/ui/controller.ts:1836`

```typescript
const inventoryContent = document.getElementById("map-list-content") || document.getElementById("inventory-content");
```

地图列表正常应写入 `#map-list-content`。当地图仪 DOM 缺失时回退写入背包，会把背包内容覆盖成地图列表，且不一定马上暴露错误。

建议：地图仪使用必需容器时直接记录错误并返回；如果确实需要兼容旧布局，应显式区分 `mapListTarget`，不要复用背包容器。

### P2：地图样式有重复 `.map-list` 定义

位置：`src/mapstyles.css:112-128`

“Map List in Map Device”和旧的“Map List in Sidebar”各定义了一次 `.map-list`，属性目前相同，但会造成维护歧义。

建议：合并为一个基础 `.map-list`，地图仪差异放到 `.map-list-panel .map-list`。

## 建议手动回归流程

1. 新游戏后依次点击角色、装备、技能、背包、任务、日志，确认每次只有一个抽屉 section 可见。
2. 重复点击当前导航图标，确认抽屉关闭，再次点击能重新打开。
3. 进入区域并探索，确认抽屉切换不影响主区域。
4. 进入战斗，尝试打开地图和天赋，确认不会出现战斗与地图叠加或状态丢失。
5. 保存后加载存档，重复点击导航、技能、药剂和天赋，确认没有重复日志或重复执行。
6. 打开地图仪、选择地图、关闭地图仪，确认返回之前的区域视图。
7. 在 700px 以下窗口检查导航、抽屉、底部药剂和技能栏是否遮挡。

## 结论

左侧导航重构的基本调用链是清晰的，普通信息面板通过统一的 `showUtilityPanel()` 管理；最大风险集中在主区域模式没有统一状态机，以及 `initGameUI()` 重复调用导致事件重复绑定。建议优先处理这两项，再收紧全局选择器和导航面板类型。
